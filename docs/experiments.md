## EXP-001 — Resize 정책과 load/resize 시간 (PHASE 1, Task 1~2)

**설정**
- `resize.max_side = 768`, `cv2.INTER_AREA`, 축소만 하고 확대하지 않음
- 25장, Intel i7-1260P, CPU, 단일 실행 (warm-up 없음)

**왜**
blur kernel, Canny threshold, texture window는 픽셀 단위이므로 해상도를 맞춰야 이미지 간 결과를 비교할 수 있다.
저해상도 이미지(011, 019)를 확대하면 보간으로 생긴 가짜 질감이 texture 분석을 왜곡하므로 확대하지 않는다.

**결과**
| 단계 | mean | max |
|---|---|---|
| load (디스크 읽기 + JPEG 디코딩) | 10.0 ms | 19.9 ms |
| resize (INTER_AREA) | 1.9 ms | 10.0 ms |

- 원본 픽셀 수가 많을수록 load가 길다 (019 285×427: 1.7 ms / 008 1200×1799: 19.9 ms).
- resize가 0.0 ms인 이미지(011, 019, 022)는 긴 변이 768 이하라 resize가 생략된 경우.
- resize max 10.0 ms는 첫 번째 이미지(001)에서만 발생 → OpenCV 첫 호출 초기화 비용(warm-up)으로 추정. 나머지 24장은 1.3~2.6 ms.

**결론**
- 전처리 비용은 디코딩이 지배적이고 resize는 무시할 수준.
- 단일 실행 + warm-up 없는 측정은 첫 호출 이상값이 섞인다. 이후 latency 측정은 warm-up 후 반복 측정하고 median을 보고한다.

## EXP-002 — HSV 통계 + LAB k-means 대표색 (PHASE 1, Task 3~4)

**설정**
- 유채색 판정: `S >= 40 and V >= 50` (HSV), 그 외 픽셀은 Hue 히스토그램에서 제외
- 대표색: LAB 공간 k-means, k=5, 샘플 20,000 px, seed 42
- 이미지 전체 대상 (silhouette 마스크 없음)

**결과 (시간)**
| 단계 | mean | max |
|---|---|---|
| color (HSV 통계 + k-means) | 18.1 ms | 106.1 ms (001, 첫 호출 warm-up) |

**결과 (관찰)**
- 무채색 사진의 achromatic 비율이 예상보다 낮음: 023_allblack 79%, 025_allwhite 15%. 024_monochrome만 98%.
- 무채색 사진(021, 023, 025)의 Hue 히스토그램에 주황/빨강 막대가 크게 나타남.

**원인 분석**
1. **HSV 채도 정의의 문제** — `S = (max - min) / max`. 밝기(max)로 나누므로 어둡거나 따뜻한 톤의 회색에서 S가 과대평가된다.

   | 색 (025 팔레트 등) | 눈으로 보면 | HSV S | HSV 판정 | LAB chroma |
   |---|---|---|---|---|
   | #776759 | 회갈색 | 64 | 유채색 | 10.8 |
   | #A1917F | 베이지 회색 | 54 | 유채색 | 12.4 |
   | #1B1B0C | 거의 검정 | 142 | (V<50이라 제외) | 8.9 |

   패션 사진은 따뜻한 톤으로 보정된 경우가 많아, 회색 배경/그림자가 "주황색"으로 집계된다.
2. **히스토그램 시각화의 문제** — 히스토그램을 자기 최댓값 기준으로 정규화해서, 유채색 픽셀이 8%뿐인 021도 막대가 꽉 차 보인다. "분포의 모양"은 보이지만 "양"은 보이지 않는다.
3. **피부/머리카락** — 주황 Hue는 실제 유채색 신호지만 의상이 아니라 사람에게서 나온다. 사람 silhouette으로도 제거되지 않음 → 의상/피부 분리가 필요 (PHASE 2 후보 문제).
4. **측정 대상의 문제** — 023의 achromatic 79%는 대부분 밝은 배경이다. 지금 통계는 "의상"이 아니라 "사진 전체"를 설명한다 → Task 8 silhouette 마스크 적용 후 재측정.

**다음 실험 (EXP-003 후보)**
유채색 판정을 HSV S 대신 LAB chroma(`sqrt(a² + b²)`, 밝기와 독립)로 바꾸고, 히스토그램 높이에 chromatic 비율을 반영해 전후 비교.

## EXP-003 — 유채색 판정: HSV S vs LAB chroma, threshold T 선택 (PHASE 1, Task 3~4)

**설정**
- 비교: `HSV S >= 40` vs `LAB chroma >= T` (T = 10, 15, 20), 25장 전체 이미지
- 재현: `python scripts/exp003_chroma_threshold.py` (비율표), `--dist` (chroma 분포)
- 시각화 수정: Hue 히스토그램 높이 × chromatic_ratio (EXP-002 원인 2)

**결과 — achromatic 비율**
| | HSV S≥40 | LAB T=10 | LAB T=15 | LAB T=20 |
|---|---|---|---|---|
| 025_allwhite | 15% | 59% | 94% | 98% |
| 023_allblack | 79% | 87% | 98% | 99% |
| 017_metalic | 49% | 72% | 98% | 99% |
| 009_complexbg (원색 장면) | 1% | 10% | 19% | 31% |
| 018_leather | 9% | 33% | 57% | 88% |
| 020_sheer | 68% | 2% | 74% | 80% |
| **mean (25장)** | **51%** | **64%** | **78%** | **85%** |

**결과 — chroma 분포 (25장 평균, 구간 폭으로 나눈 밀도 %/unit)**
| 0-5 | 5-10 | 10-12 | 12-14 | 14-16 | 16-18 | 18-20 | 20-25 | 25-30 | 30-40 |
|---|---|---|---|---|---|---|---|---|---|
| 8.1 | 4.7 | 4.3 | 2.3 | 1.4 | 1.05 | 1.3 | 0.82 | 0.70 | 0.56 |

**분석**
- LAB chroma는 따뜻한 톤의 회색을 무채색으로 올바르게 판정 (025: 15% → 94%), 원색 장면 009는 19%로 낮게 유지 → HSV 대비 개선.
- 020: 픽셀 64.8%가 chroma 10~12 (베이지 종이 배경)에 집중 → T가 이 구간을 지날 때 결과가 2% → 74%로 급변. **threshold를 밀집 구간에 두면 불안정**하다.
- 25장 평균 분포는 구간 폭을 보정하면 뚜렷한 bimodal valley가 없는 단조 감소(long tail). 회색↔유채색은 연속적이며 자연스러운 경계가 없다. (구간 폭이 다른 히스토그램을 그대로 비교하면 14~18이 valley처럼 보이는 착시가 생긴다.)
- 정답이 정의에 따라 갈리는 사례: 020 베이지 배경, 018 푸른 조명 배경 (chroma 12~25에 분산, 어떤 T에서도 불안정).

**결정: T = 15 (잠정)**
- ① Anchor case: 확실한 무채색 영역(025, 012의 회색 배경)은 chroma ≤ 14가 87~91% → T ≥ 14. T=20에서는 011(60→80%), 018(57→88%)의 실제 색이 사라지기 시작 → T < 20.
- ② Valley: 020, 012, 016, 021 등 개별 이미지에서는 14~18 구간이 희소. 데이터 전체 기준으로는 약한 근거.

**남은 문제 → 다음 단계**
1. 현재 T는 배경 픽셀이 지배하는 분포로 정해졌다. 측정 대상(의상)과 다름 → Task 8 silhouette 이후 사람 영역만으로 재확인.
2. 최적 T는 정답 정의 + 목표(precision vs recall)가 있어야 결정 가능 → PHASE 3에서 patch GT 라벨링 후 precision-recall 곡선으로 확정. 우선 확인 대상: T 근처 픽셀 비중이 큰 005, 012, 018.
3. 피부는 실제 유채색 → 사람 silhouette으로도 제거 불가, 의상/피부 분리 필요 (PHASE 2 문제 정의 후보).

## EXP-004 — Canny threshold: fixed vs auto(median) (PHASE 1, Task 5~6)

**설정**
- 전처리: grayscale → GaussianBlur 5×5 (cv2.Canny는 blur를 포함하지 않음)
- fixed: (100, 200) — baseline / auto: (1 ± 0.33) × 밝기 median
- contour: `RETR_LIST`, 길이 50px 미만 제외
- 시간: edge 단계 median 5.6 ms (두 방식 Canny + contour 포함)

**결과 — 그룹별 edge density (fixed)**
| plain | complexbg | pattern | glossy | sheer | mono |
|---|---|---|---|---|---|
| 1.0% | 5.3% | 5.2% | 2.6% | 2.0% | 3.2% (023: 1.2%, 024: 0.7%, 025: 7.7%) |

- edge density는 대비의 "세기"가 아니라 경계선의 "총 길이"를 잰다. 검은 옷 + 흰 배경(023, 024)은 대비는 강하지만 선이 외곽선 하나뿐이라 density가 가장 낮은 축에 속한다.
- 025가 mono 그룹에서만 높은 것은 옷이 아니라 거리 배경 때문 → 그룹 평균도 배경에 좌우된다.

**결과 — auto threshold의 실패 양상**
| 이미지 | 밝기 조건 | auto T | density fixed → auto |
|---|---|---|---|
| 022_sheer | 밝은 배경 | 148 / 255 | 0.5% → 0.2% |
| 020_sheer | 밝은 배경 | 131 / 255 | 1.2% → 0.7% |
| 009_complexbg | 어두움 | 33 / 66 | 4.2% → 11.2% |
| 019_satin | 매우 어두움 | 5 / 10 | 3.2% → 12.3% |

- auto는 장면을 "이해"하지 않고 밝기 median 숫자 하나만 본다.
- Canny threshold는 밝기가 아니라 **gradient 크기(이웃 픽셀 간 차이)**에 적용된다. 밝기 median은 gradient 크기와 직접 관계가 없다 → 균일한 배경이 화면을 지배하면 median이 배경 밝기를 따라가 threshold가 양극단으로 튄다 (상한 255 포화, 또는 5/10처럼 노이즈 수준).

**정성 관찰 (contour 패널)**
- 023 (단색 배경): 가장 긴 contour가 실제로 인물 외곽선. 단, 머리(금발 vs 밝은 배경)와 손에서 끊겨 닫힌 곡선이 아니다.
- 007 (복잡한 배경): 가장 긴 contour는 배경의 비계 기둥. 인물 edge는 조각나 있다.
- 013 (패턴): density 9.2%의 대부분은 셔츠 줄무늬가 아니라 배경 셔터의 가로선. 가는 줄무늬는 5×5 blur에서 대부분 사라졌다 → edge는 미세한 패턴을 재는 도구가 아니다 (Task 7 texture의 근거).

**결정: method = fixed (100, 200)**
- resize(768) + 동일 blur 이후에는 이미지 간 gradient 스케일이 비슷해 고정값이 일관된 결과를 준다.
- auto는 밝은/어두운 배경 양쪽에서 불안정. 필요해지면 밝기가 아닌 gradient 크기의 percentile 기반 threshold를 후보로 검토.

**결론 — edge만으로 silhouette을 만들 수 없는 이유**
1. 끊김: 대비가 약한 구간에서 외곽선이 닫히지 않는다 (023 머리).
2. 소속 불명: edge는 그 선이 사람의 것인지 배경의 것인지 모른다 (007, 013).
3. 내부 edge: 주름, 라펠, 무늬 경계가 외곽선과 섞인다.
→ silhouette은 경계(edge)가 아니라 영역(region) 기반 방법이 필요하다 (Task 8: GrabCut).

## EXP-005 — Silhouette: Otsu vs GrabCut (PHASE 1, Task 7) — 1차 (정성 평가, GT 전)

**설정**
- Otsu: gray → blur 5×5 → Otsu threshold, 테두리 과반 쪽을 배경으로 판정
- GrabCut: 중앙 사각형 초기화 (좌우 5%, 상하 2% 여백), 5 iterations, seed 42, 계산 해상도 ×0.5
- 공통 후처리: closing → opening (7×7 ellipse) → 가장 큰 연결 덩어리

**결과 — 시간 (25장)**
| 방법 | median | max |
|---|---|---|
| Otsu | 4.6 ms | 6.3 ms |
| GrabCut ×0.5 | 796 ms | 2,603 ms |
| GrabCut ×1.0 (사전 측정 3장) | 2,899 ~ 12,983 ms | |

- GrabCut은 Otsu보다 약 170배 느리고, 반복 최적화라 이미지에 따라 시간이 18배까지 달라진다 (143 ~ 2,603 ms).
- 해상도를 절반으로 낮추면 5~10배 빨라진다. 023에서는 ×1.0 결과에 배경 덩어리가 붙고 ×0.5가 더 깔끔했다 (3장 관찰, GT 검증 필요).

**결과 — 정성 분류 (패널 육안 판단, 측정값 아님)**
| | 대체로 성공 | 부분 성공 (배경 일부 포함 / 신체 일부 누락) | 실패 |
|---|---|---|---|
| GrabCut | 002 004 005 011 016 017 018 019 020 021 022 023 025 (13) | 001 006 008 010 012 013 014 024 (8) | 003 007 009 015 (4) |
| Otsu | 019 022 024 (+ 구멍/누락 있는 016 023 025) | | 나머지 대부분 |

**실패 원인 분류**
1. 밝기 하나로는 부족 (Otsu): 사람 안에 밝은 부분과 어두운 부분이 함께 있으면 한쪽만 잡는다 (001: 남색 바지 + 파란 바닥만 선택, 023: 머리 누락). 사람이 배경보다 균일하게 어둡거나 밝을 때만 성공 (024).
2. 느슨한 초기 사각형 (GrabCut): 사각형이 이미지의 약 90%를 덮어 배경 대부분이 "아마 전경"으로 시작한다 → 전경 색 모델에 배경색이 섞인다 (003: 나무 벽, 015: 건물, 024: 배경 덩어리).
3. 사각형 가정 위반 (GrabCut): 중앙에 서 있지 않은 사람(009: 누워 있음), 두 사람(008: 한 명만 선택).
4. 색이 비슷한 영역: 010, 013에서 머리가 누락 (원인 미확정 — 배경과의 색 유사 또는 상단 여백).
5. 반투명 소재: 021의 튤, 020·022의 시스루는 GrabCut mask에 포함됨. 다만 반투명 픽셀은 천과 배경이 섞인 색이라 0/1 mask로는 정확히 표현할 수 없다 (정의의 문제).

**agreement IoU (두 방법 간 일치도)의 쓸모**
- 0.8 이상인 6장(016 019 022 023 024 025)은 모두 두 방법이 대체로 성공한 쉬운 사진.
- 낮다고 어느 쪽이 맞는지는 알 수 없다 (002: 0.00이지만 GrabCut은 성공).

**다음**
GT mask 10장으로 IoU 측정 → Otsu vs GrabCut(×1.0 / ×0.5 / ×0.33) 정량 비교 후 method와 scale 확정.
2, 3번 원인은 사람 위치를 아는 tight bbox가 있으면 해결 가능 → PHASE 2 person detector 도입 근거.
